shitate は、サイトエディター（フルサイト編集）専用の WordPress ブロックテーマです。コーポレートサイト・ビジネスサイト向けに、依存ライブラリなしの軽量な出力と、ひとつの数値からサイト全体の見た目が決まる「トークン駆動のデザインシステム」を組み合わせています。このページはテーマの公式マニュアル兼設計書です。

このテーマの考え方

shitate の設計は、次の 4 つの原則の上に成り立っています。設定項目を増やすのではなく、少数の基準値から全体が導かれるようにすることで、誰が編集しても崩れにくいサイトを目指しています。

  • ひとつの比率がすべてを決める — 文字サイズも余白も、同じ「基準サイズ × 比率」から機械的に生成されます。カスタマイザーで比率を変えると、見出しの大きさもセクションの余白も同時に、破綻せずに変わります。
  • メディアクエリを書かない — 画面幅ごとの分岐ではなく、clamp とグリッドの自動折り返しでレスポンシブを実現しています。狭い画面ではリズム全体が自動的に締まります。
  • 縦の余白は上方向だけ — 要素の上マージンだけで縦のリズムを作ります。上下からマージンが来て相殺されたり二重になったりする事故が起きません。
  • 色はパレットがすべての起点 — サイトエディターのパレットを編集すれば、テーマの CSS 変数もプラグインのブロックも自動的に追従します。

動作要件

インストールと初期設定

  1. 「外観 → テーマ → 新規追加」からテーマをインストールし、有効化します。
  2. 「外観 → エディター」でサイトエディターを開き、ヘッダーのロゴ（サイトロゴブロック）とナビゲーションメニューを設定します。
  3. 「外観 → エディター → スタイル」でスタイルバリエーション（Dark / Cream / Mist / Mono）を選ぶか、パレットの色を自分のブランドカラーに変更します。
  4. 「外観 → カスタマイズ → Typography Scale」で本文サイズとスケール比率を決めます。ここがサイト全体の見た目の基準になります。
  5. 固定ページを作り、「表示設定」でホームページに指定します。トップページ用のテンプレートには、テーマ同梱のパターンが最初から並んでいます。

パターンの管理画面へは「外観 → パターン」から直接ジャンプできます（ブロックテーマではエディターの奥に埋もれてしまうため、テーマ側でショートカットを追加しています）。

デザインシステム

テーマ独自の値はすべて assets/css/tokens.css に --st- 接頭辞の CSS 変数として定義されています。theme.json の custom セクションは使っていません。変数の見分け方はシンプルです。

  • --st-* … このテーマが定義した変数。カスタム CSS ではこちらを使ってください。
  • --wp--* … WordPress が theme.json から自動生成した変数。

色

色の正本は theme.json のパレットです。サイトエディターの「スタイル → 色」でそのまま編集でき、スタイルバリエーションもパレットを差し替えるだけの仕組みになっています。--st-color-* はパレットへの短いエイリアスなので、パレットを変更すればカスタム CSS もプラグインのブロックも自動的に追従します。

パレットを自分で増やすときの注意: スラッグに border や background といった、WordPress が構造用のクラス名として使う語を選ばないでください。たとえば border というスラッグはコアに .has-border-color という文字色のクラスを生成させ、枠線を設定したブロックの文字色を意図せず上書きします。このテーマが枠線色のスラッグを line にしているのはそのためです（表示名は「Border」のままです）。

文字サイズ

typescale.com と同じ考え方のモジュラースケールです。基準サイズ（既定 16px）に比率（既定 1.25）を掛け続けて 8 段を生成します。段はエディターのフォントサイズ選択肢としてそのまま使えます。

本文の行間は 1.75、見出しは 1.3・太さ 700 です。フォントは日本語環境を優先した OS 標準スタックで、Sans-serif（既定）・Serif（明朝）・Monospace の 3 種を用意しています。Web フォントは同梱していません。

余白

余白は文字サイズとまったく同じ規則で作られた 8 段のモジュラースケールです。--st-space-xxs から --st-space-xxxl まで、文字サイズと同じ名前で並びます。基準は m で、これが本文サイズと一致し、そこから離れるほどスケール比率が掛かっていきます。つまりカスタマイザーで比率や本文サイズを変えると、余白も同時に追従します。

既定の比率 1.25 では、およそ 4.2 / 5.2 / 6.6 / 8.2 / 10.2 / 12.8 / 16 / 20 / 25 / 31 / 39 / 49 / 61 / 76 / 95px という並びになります。比率を小さくすると余白全体が締まり、大きくすると開きます。これは等比スケールの正しい挙動で、仕様です。

8 段目以上は流体です。狭い画面では「(1 + 比率) ÷ 2」から導かれる控えめな比率まで自動的に縮み、広い画面で選択した比率いっぱいまで開きます。メディアクエリを一切書かずにモバイルの余白過大を防ぐ仕組みです。1〜6 段目は差が数ピクセルで知覚できないため固定値のままにしています。

エディターの余白ピッカーには、15 段のうち使いやすい 8 段だけを公開しています（15 個並ぶと選べなくなるため）。中間の段も CSS 変数としては利用できます。

旧来の T シャツ名（--st-space-xxs 〜 --st-space-xxxl）も、上表の段へのエイリアスとして引き続き使えます。保存済みのコンテンツやユーティリティクラスとの互換のためです。

縦のリズム

ブロック同士の基本の間隔は WordPress の blockGap（既定で L＝約 25px）が担当し、上マージンとして適用されます。見出しの前だけは、階層が読み取れるように広めの余白が入ります。

  • h1・h2 の前 … その場所の基本間隔 × 1.75
  • h3・h4 の前 … その場所の基本間隔 × 1.25

固定値ではなくその場所の間隔に対する倍率なので、間隔を詰めたカードやボックスの中では見出し前の余白も自動的に詰まります。ブロックの先頭要素には上マージンが付きません。ユーティリティクラスなどで明示指定した値は、従来どおりそちらが優先されます。

この方針を保つため、すべてのコアブロックの余白設定は「上マージンのみ」に制限されています。ブロックのサイドバーに下マージンの入力欄が出ないのは仕様です。

幅・角丸・影

幅を rem で指定しているため、閲覧者がブラウザの文字サイズを大きくすると 1 行の長さもそれに合わせて調整されます。角丸は 3 語彙だけに統一しており、px の直書きは行いません。

カスタマイザー「Typography Scale」

「外観 → カスタマイズ → Typography Scale」に、サイト全体の見た目を決める 3 つの設定があります。比率と基準サイズはライブプレビューで即座に反映されます。

比率を変えると文字と余白が同時に変わります。「もう少し全体を締めたい」ときは比率を 1.2 に、「見出しを大きく見せたい」ときは 1.333 以上に、といった調整が 1 か所で完結します。

スタイルバリエーション

「外観 → エディター → スタイル」から 4 種類のバリエーションを選べます。いずれもパレットを差し替えるだけで、レイアウトや余白の設計には手を入れていません。ブランドカラー（primary #2952cc）はどのバリエーションでも共通です。

テンプレート

テンプレートパーツはヘッダーとフッターの 2 つです。ヘッダーはロゴ＋サイトタイトルを左、ナビゲーションを右に配置。フッターは濃色背景で、サイトタイトル・キャッチフレーズ・縦並びナビ・著作権表示という構成です。

同梱パターン

ブロック挿入ツールの「パターン → shitate」から挿入できます。いずれもコアブロックだけで作られているので、プラグインを入れなくてもそのまま使えます。

各セクションは section 要素・全幅・上下パディング XXL（ヒーローのみ XXXL）で統一されています。文言はすべて差し替え前提のサンプルです。

余白ユーティリティ

ブロックのサイドバーで細かく数値を触らずに済むよう、余白用のクラスを用意しています。クラス名は「プロパティ＋方向＋段」という組み立てです。

  • プロパティ … m＝マージン、p＝パディング
  • 方向 … t 上 / r 右 / b 下 / l 左 / x 左右 / y 上下 / 省略で全方向
  • 段 … 0 / xxs / xs / s / m / l / xl / xxl / xxxl

例: mt-0（上マージンを消す）、mb-l、px-m、py-xxl、p-s。左右中央寄せの mx-auto もあります。

クラスを手入力しなくても、ブロックのツールバーに追加される「余白」ドロップダウンから、上下マージン・上下パディング・左右パディング・中央寄せを選ぶだけで付け外しできます。

カスタム CSS を書くときのルール

追加 CSS や子テーマでスタイルを足すときは、次のトークンを参照してください。数値を直接書かずに変数を使えば、カスタマイザーの設定変更やスタイルバリエーションの切り替えに自動で追従します。

/* 色 */
--st-color-brand         ブランドカラー
--st-color-brand-hover   ブランドカラー（ホバー）
--st-color-accent        差し色
--st-color-base          背景
--st-color-base-2        背景（塗り分け）
--st-color-contrast      本文の文字色
--st-color-contrast-2    補足テキスト
--st-color-neutral       メタ情報
--st-color-border        罫線

/* 文字 */
--st-text-xxs / xs / s / m / l / xl / xxl / xxxl
--st-ratio               スケール比率

/* 余白 */
--st-space-xxs 〜 --st-space-xxxl   （m が基準＝本文サイズ）
--st-space-xxs / xs / s / m / l / xl / xxl / xxxl   （旧名エイリアス）

/* レイアウト・装飾 */
--st-width-text          コンテンツ幅
--st-width-max           幅広
--st-radius-s / m / l    角丸
--st-border-card         カードの枠線

テーマ本体のスタイルでは !important とメディアクエリを使わない方針です。可変幅は clamp と自動折り返しグリッドで解決してください。!important が許されるのは余白ユーティリティの層だけです。

拡張プラグイン shitate pro blocks

テーマにはブロックを同梱していません。FAQ、吹き出し、モーダル、条件分岐表示、アクションフック、レイアウト、アコーディオン、スライダーなどのブロックは、有料プラグイン shitate pro blocks が提供します。

プラグイン側のブロックは、テーマがある環境ではテーマのトークン（--st-*）を自動的に使い、テーマがない環境では組み込みの初期値で動作します。どちらの組み合わせでも見た目が破綻しない設計です。デバイス出し分けの境界（768px / 1024px）もテーマ側の設定と揃えてあります。

よくある質問

ブロックに下マージンの設定が出てきません

仕様です。このテーマは縦の余白を上マージンだけで組み立てているため、コアブロックの余白設定を上方向に限定しています。要素の下に余白を足したい場合は、次の要素の上マージンを調整するか、ユーティリティクラス（mb-l など）を使ってください。

余白ピッカーの選択肢が 8 つしかありません

これも仕様です。余白の段は文字と同じ 8 つで、ピッカーにはその 8 段をそのまま公開しています。中間のサイズが必要な場合は、カスタム CSS で calc(var(--st-space-m) * var(--st-ratio)) のように比率を掛けて作れます。

アイキャッチ画像がぼやけます

以前のテーマが定義していた小さい画像サイズが残っている可能性があります。shitate はアイキャッチを幅 1568px（等比・切り抜きなし）で扱いますが、既存のアップロード画像にはこのサイズがまだ生成されていません。サムネイル再生成のプラグイン、または wp media regenerate を実行してください。

枠線を設定したら文字の色まで変わりました

パレットに border というスラッグの色を自分で追加していないか確認してください。WordPress はそのスラッグから .has-border-color という文字色用のクラスを生成し、枠線用の構造クラスと名前が衝突します。スラッグを別名に変更すれば解消します。

比率を上げたら余白が大きくなりすぎました

文字と余白が同じ比率を共有しているため、比率を上げると余白も等比で開きます。全体の間隔だけを抑えたい場合は、サイトエディターの「スタイル → レイアウト」でブロック間の間隔（blockGap）を 1 段下げてください。見出し前の余白はそれに連動して自動的に締まります。

├ readme.txt             WordPress.org 用

├ assets/js/customize-preview.js   カスタマイザーのライブプレビュー

命名規則

  • st ＝ shitate theme。PHP 関数 st_、定数 ST_、ハンドル st-、CSS 変数 --st-*、パターン st/*（カテゴリー st）
  • sb ＝ shitate block（プラグイン側）。テーマは --sb-* を定義しません
  • 例外: テキストドメインは shitate。WordPress.org がテーマスラッグとの一致を要求するためです

functions.php が行っていること

  • テーマサポートの登録、アイキャッチサイズ 1568×9999 の定義、エディタースタイルの読み込み、翻訳の読み込み
  • パターンカテゴリー st の登録
  • 「外観 → パターン」メニューの追加（サイトエディターのパターン画面への直リンク）
  • register_block_type_args フィルタで、すべてのコアブロックの余白サポートを上マージンのみに制限
  • カスタマイザーのスケール設定と、そこから生成する CSS の出力。フロントは tokens.css の直後にインラインで、エディターは block_editor_settings_all 経由で iframe 内に注入します
  • スタイルの読み込み順は st-tokens →（スケール上書き）→ st-utilities → st-style。この順序が前提になっています

翻訳の更新

翻訳辞書と抽出スクリプトはプラグイン側にまとめて置いてあります（テーマとプラグインを横断管理するため）。

cd ../../plugins/shitate-pro-blocks && node bin/make-i18n.mjs
cd - && msgfmt languages/shitate-ja.po -o languages/ja.mo

JavaScript の翻訳 JSON は shitate-ja-st-utilities-toolbar.json のようにハンドル名で命名します（WordPress はハッシュではなくハンドル名で探します）。なお、テンプレート HTML 内に直接書かれた英文（フッターの著作権表示、404 の文言など）は翻訳できない既知の制約です。

ビルドとリリース

bin/build-zip.sh          配布用 dist/shitate.zip を生成
bin/release.sh X.Y.Z      バージョン一括更新 → commit → tag → zip → push → Release
  1. CHANGELOG.md の [Unreleased] にたまった項目を「## [X.Y.Z] - YYYY-MM-DD」セクションに移す
  2. bin/release.sh X.Y.Z を実行する。style.css の Version、readme.txt の Stable tag、functions.php の ST_VERSION がまとめて更新されます
  3. readme.txt の Changelog セクション（WordPress.org の審査対象）に、同じ内容をユーザー向けの表現で手動反映する

WordPress.org 掲載にあたっての制約

  • 自動アップデート機構を再導入しない。 公式ディレクトリ掲載中は Update URI ヘッダも外部通信も禁止です。GitHub 経由の配信機構は 0.3.0 で削除済みで、実装履歴は Git の 0.2.0 に残っています
  • フォント・画像・外部ライブラリを同梱しない（すべて自作物のみ）
  • 配布 zip で Theme Check がパスすることを確認してからアップロードする
  • タグは公式の許可リストに準拠させる
